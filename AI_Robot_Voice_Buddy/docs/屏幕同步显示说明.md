# 屏幕文字与语音同步显示（打字机式）

> 2026-09-25 新增，解决"屏幕先出整段文字、语音滞后"的问题。

## 效果

- 发起 TTS 请求时**屏幕不显示**文字，避免声音未响、文字先出的错位；
- 语音**真正开始出声**（百度 TTS 的 MP3 首帧解码成功）时，文字才开始**逐字出现**，节奏与语音一致；
- 一段播报结束（或下一段开始时）**补全整段文字**；
- 文字超过一屏（5 行约 50 字）时，像提词器一样**滚动显示末尾几行**；
- 提问（用户说的话）同样用滚动窗口显示，长提问不再被截断。

## 实现要点

| 内容 | 位置 |
|---|---|
| 所有播报统一入口 `speakAndDisplay()` | 原来 voicePlay / processResponse / response / 音乐应答里各自 connecttospeech + 显示，现全部收口到这里 |
| 真正出声检测 | `audio2.getBitRate() > 0`：`setDefaults()` 每段请求会把码率清零，MP3 首帧解码后才写入码率，是**最接近出声时刻**的可靠信号（比 `isplaying` 可靠——后者在发起 HTTP 请求时就置 1 了） |
| 语速估算 | `charMs()`：中文每字 190ms、ASCII 90ms、句末标点附加 250ms（按百度 TTS spd=6 估算） |
| 逐字渲染 | `displayProgress()`：只渲染前 N 字节，按屏宽自动换行，超一屏显示最后 5 行 |
| 重绘节流 | loop() 中仅当"应显示字节数"变化（即出现新字符）才重绘，每字约一次 |

## 调参

如果觉得文字比语音快/慢，改 [main.cpp](../src/main/main.cpp) 的 `charMs()`：

```cpp
int ms = size == 3 ? 190 : 90;   // 中文每字 190ms、ASCII 90ms，改大=显示更慢
ms += 250;                       // 标点附加停顿
```

## 踩坑记录（勿再犯）

1. **重绘风暴**：按"已显示毫秒数"比较触发重绘，会导致每帧 loop 都整屏重绘 OLED（每次约 30ms 阻塞），抢 CPU 造成**语音开头卡顿**。必须按**字符边界字节数变化**触发。
2. **`String::substring(a, b)` 第二参数是"结束位置"不是"长度"**：误当长度使用时，第二行起参数互换，出现行内容重复错乱。正确写法 `substring(pos, pos + lineBytes)`。
3. **wqy12 chinese1/2/3 字体子集只有几百字**，常用字如「待」会缺字（屏幕显示空白）。已换 `u8g2_font_wqy12_t_gb2312`（GB2312 全集 7533 字，约 198KB Flash，16MB 板子无压力）。注意此 `_t_` 字体是 Unicode 输入（UTF-8 源码正常）；会乱码的是 gb16st/gb24st 那种 GB2312 字节编码字体。

## 相关状态变量（main.cpp 顶部）

- `syncText`：当前播报中、需同步显示的文字段
- `syncTotalMs` / `syncShownBytes`：预估总时长 / 已显示字节数
- `syncStarted` / `syncStartMs` / `syncReqMs`：出声标志 / 出声时刻 / 请求时刻（TTS 失败 3 秒兜底补全显示）
